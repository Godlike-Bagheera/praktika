# Перенос проекта «Форум» через экспорт ВМ (.ova) — полная проверка инструкции

Инструкция проверена по фактическому состоянию репозитория (коммит 5d0c48c).
Ниже — твоя инструкция с пометками: что верно, а где есть подводные камни.

## ЧАСТЬ 1: Сохранение (на текущем ПК)

### Шаг 1. Подготовка кода — ВЕРНО ✅
```bash
cd praktika
git pull
docker compose up -d --build
```
Дополнительно (рекомендую): сделай SQL-дамп как резервную копию на случай,
если .ova повредится или вес будет слишком большим для флешки:
```bash
bash scripts/backup.sh    # создаст forum_backup_<дата>.tar.gz (БД + .env)
```

### Шаг 2. Выключение — ВЕРНО ✅ (но недостаточно для докера)
```bash
sudo poweroff
```
⚠️ Важно: `poweroff` останавливает ОС, но Docker-контейнеры при выключении ВМ
останавливаются автоматически только если включён автозапуск compose. Чтобы
контейнеры стартовали сами на новом ПК, выполни ПЕРЕД poweroff:
```bash
cd ~/praktika && docker compose down          # корректно остановить контейнеры
sudo systemctl enable docker                  # докер стартует при загрузке
# включить автостарт проекта при загрузке:
crontab -l 2>/dev/null | grep -v praktika; ( crontab -l 2>/dev/null; echo "@reboot cd $HOME/praktika && docker compose up -d" ) | crontab -
```
Тогда на новом ПК команда из Шага 3 части 2 вообще не понадобится — всё само.

### Шаг 3. Экспорт OVA — ВЕРНО ✅
Файл → Экспортировать конфигурацию → формат OVA. Вес ~5–10 ГБ (ОС + образы
Docker + том pgdata со всей базой). Это буквально вся машина целиком.

## ЧАСТЬ 2: Запуск на новом ПК

### Шаг 1. Импорт — ВЕРНО ✅ + важное замечание про MAC
«Generate new MAC addresses» — правильно ставить. НО: после смены MAC
Ubuntu может получить ДРУГОЙ IP от DHCP (например, 10.0.2.16 вместо 10.0.2.15).
Это НИКАК не ломает сайт, потому что nginx слушает 0.0.0.0:80 внутри ВМ,
а доступ идёт через проброс портов NAT (по localhost, не по IP ВМ).
Если заходить по IP ВМ — обнови DJANGO_ALLOWED_HOSTS в ~/praktika/.env
и выполни `docker compose restart app`.

### Шаг 2. Сеть и проброс портов — ВЕРНО ✅ (именно так и надо)
NAT + две строки:
- web: TCP, порт хоста 8084 → порт гостя 8084
- ssh: TCP, порт хоста 2222 → порт гостя 22

Проверено в репозитории: docker-compose.yml публикует `"8084:80"`, то есть
nginx-контейнер слушает 8084 ХОСТА ВМ → проброс VirtualBox 8084→8084 верный. ✅
(Порт 5432 наружу не публикуется нигде — база недоступна извне, как требует ТЗ.)

### Шаг 3. Запуск — ВЕРНО ✅
Логин user / пароль — это твои учётные данные Ubuntu, которые ты задавал при
установке (Password123! — проверь, что помнишь именно его; в проекте он нигде
не хранится и заменить его нельзя, только помнить).
```bash
cd praktika && docker compose up -d
```
Если сделал crontab из Шага 2 — эту команду можно не вводить, всё уже поднято.
Проверить статус: `docker compose ps` (db healthy, app running, nginx running).

### Шаг 4. Проверка — ВЕРНО ✅
http://localhost:8084 — откроется форум со ВСЕМИ данными: пользователи
(включая admin@gmail.com/admin), роли, категории, темы, сообщения — они лежат
в томе pgdata внутри .ova. Вход работает сразу, перелогиниваться не нужно
(JWT в httpOnly-куках выдаются заново при входе).

## Итоговый вердикт по инструкции
Все 7 шагов корректны. Три уточнения, которые стоит добавить:
1. Перед poweroff — `docker compose down` + crontab @reboot (иначе на новом ПК
   придётся вручную вводить `docker compose up -d`, что у тебя и так есть в Шаге 3,
   так что это опционально).
2. После импорта IP ВМ может измениться — на доступ через localhost:8084 это
   не влияет; влияет только если открываешь по IP ВМ (тогда правь ALLOWED_HOSTS).
3. Сделай дополнительно `bash scripts/backup.sh` — форум-данные будут продублированы
   в SQL-дампе на случай битого/гигантского .ova. Восстановить из него можно
   одной командой: `bash scripts/deploy_new_pc.sh forum_backup_<дата>.tar.gz`.

## Быстрая шпаргалка (что реально делать)
Сохранить: git pull → docker compose up -d --build → bash scripts/backup.sh →
docker compose down → sudo poweroff → экспорт OVA → скопировать .ova + backup.tar.gz.
Запустить: импорт OVA (new MAC) → NAT + пробросы 8084/2222 → старт →
cd praktika && docker compose up -d → открыть http://localhost:8084.
